# Revisões da v0.4.0

Data: 02/11/2026. Code review e bug review locais, em passagens separadas pelo
implementador; não representam revisão independente. Contrato ai-memory v3.3.1
conferido nas rotas administrativas, handlers MCP e tipos serializados upstream.

## Code review

| Achado | Correção / evidência |
| --- | --- |
| Detalhe de proposta possui wrapper Rust flatten no JSON | Leitura de `summary` no nível raiz, ID e estado pending validados; diff deve repetir o ID; teste `proposal_review_requires_pending_status_and_loads_scoped_diff` |
| Prévia/confirmacão poderia atravessar troca de conexão ou expirar | Recibo imutável com geração e prazo de 5 minutos, validado ao enfileirar e executar; conexão bloqueada na UI durante a operação; teste `expired_and_previous_connection_receipts_never_dispatch` |
| Falha de escrita pode ter efeito apesar de perder resposta | Retry desabilitado, recibo consumido, aviso de resultado incerto; teste verifica um único POST sob HTTP 503 |
| Cancelamento/MCP stateful exige inicialização e controle de sessão | Handshake, notification sem ID, cabeçalho de sessão, leitura JSON/SSE até resposta correlacionada e fechamento do transporte; teste com servidor sintético |
| Reconsolidação não recebe escopo no contrato MCP | ID explícito obrigatório, aviso de destino escolhido pelo servidor e confirmação `SESSAO <id>`; sem alegar restrição ao projeto do seletor |
| Backups poderiam sobrescrever arquivo ou ser públicos | `create_new`, modo 0600, limite de bytes/tempo, fluxo em blocos e remoção de parcial em erro; teste de permissão, sobrescrita e limpeza |

Rotas foram conferidas individualmente. Lint força `no_llm=true`; curadoria
aplicada usa stage; embeddings nunca usam all_projects; todas as prévias de
manutenção explicitam dry_run. Não foi implementado falso dry-run de auto-improve.
O código de cancelamento de handoff força any_owner=false. Erros não ecoam o corpo
privado do servidor. Não há escrita na memória real durante os testes.

## Bug review

| Achado | Correção / evidência |
| --- | --- |
| Comparação automática de versão antiga não seria prévia fiel da restauração | Carrega ID atual e solicita diff atual → versão escolhida; teste `restore_preview_compares_current_version_to_requested_version` |
| Relatório genérico poderia exibir campos indevidos de handoff redacted | Campos de prompt removidos antes de chegar ao relatório; regressão `redacted_handoff_text_cannot_reach_the_admin_report` |
| Evidências extensas poderiam ser omitidas sem navegação | Listas paginadas de 100, aviso para textos acima de 100 KiB/profundidade, IDs de árvore com contexto |
| Formulários/recibos poderiam preservar dados da conexão anterior | Reset limpa resultado, confirmação e campos privados; teste dedicado de UI |
| Tipo da assinatura gzip e guard de caminho impediam checks limpos | Tipos e match corrigidos; testes e Clippy aprovados |

Smoke nativo com HTTP sintético confirmou lista de propostas, seleção de ID,
evidências/diff, campos bloqueados, confirmação inicialmente desabilitada,
habilitação após digitar o escopo e envio único de aprovação. A prévia de lint
foi cancelada: o log sintético confirmou somente POST dry_run=true/no_llm=true,
sem aplicação. Controles de backup/restauração também inspecionados. App encerrado.

## Verificações concluídas

- Fmt e `git diff --check`.
- 52 testes Apple Silicon e 52 Intel via Rosetta; zero falhas.
- Clippy em todos os targets, warnings tratados como erro.
- DMG Universal criado; assinatura, montagem, cópia e execução após ejeção aprovadas.
- Fixtures não substituem homologação de servidor real, backup restaurado, Intel
  físico ou versões antigas do macOS. O conteúdo gzip não é testado por restauração.

Zero achados acionáveis abertos nessas revisões locais. CI do PR deve aprovar o
commit final antes do merge e da publicação.
