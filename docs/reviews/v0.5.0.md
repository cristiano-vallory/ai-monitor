# Revisões da v0.5.0

Data: 02/11/2026. Code review e bug review locais, em passagens separadas pelo
implementador; não representam aprovação independente. Contrato conferido no
ai-memory v3.3.1, commit `1c506228b701f4496d3d9af6f00180749e0563d1`, nos handlers
administrativos, auth, perfil, workstreams e tipos do CLI.

## Code review

| Achado | Correção / evidência |
| --- | --- |
| Cookie humano poderia conviver com Bearer e autenticar como outra identidade | Transporte escolhe explicitamente uma classe; auth/login não recebe Bearer, sessão envia cookies/CSRF; 401 não faz fallback; testes de requisição única |
| Logout retorna 204; mudança de senha renova cookies | Resposta 204 aceita sem tentar JSON; ambos os cookies substituídos; testes de rotação/CSRF |
| Login/password poderiam expor credenciais em HTTP remoto | Validação de HTTPS antes de enviar senha; cookies inválidos/ausentes falham fechados; testes sem rede externa |
| Persistência poderia misturar servidores ou contrariar token de ambiente | Keychain opcional por URL/base path; JSON omite segredos; endereço alterado limpa autenticação; variável de ambiente explícita tem prioridade, inclusive vazia |
| Prévia de excluir workspace em versão antiga poderia apagar workspace vazio | Essa prévia sempre usa GET de inventário, nunca POST; teste inclui lista vazia |
| Algumas operações não possuem dry-run | Catálogo separa simulação real de consulta de estado; merge-project/move-session usam confirm=false e purge usa dry_run=true/confirm=false; teste percorre todas as operações |
| Rota de acesso ao projeto não coincide com nome interno do handler | Corrigida para `/admin/projects/access`, conferida no router upstream |
| Cancelar inbox sem ID cancelaria todo o lote | ID obrigatório validado antes de HTTP; leitura somente GET; teste comprova ausência de requisição ao faltar ID |
| Respostas administrativas incluem segredos novos | Ocultação recursiva, revelação explícita, limpeza/troca/expiração; sem persistência ou logs |
| Operação Docker poderia atingir contexto remoto ou outro contêiner após prévia | Ambiente restrito, contexto Unix, vínculo ao ID/imagem/labels, revalidação antes da ação; teste com executável sintético e troca de ID/contexto |
| Compose pode mudar por interpolação sem alterar YAML | Digest da configuração resolvida em memória; confere antes/após pull; saída nunca exibida; sem build, prune, down ou remoção de volumes |
| Atualização nativa poderia sobrescrever binário sem recuperação | Serviço parado, hash esperado, cópia privada do anterior, staging e rename atômico; teste de hash divergente e backup preservado |

## Bug review

| Achado | Correção / evidência |
| --- | --- |
| Resultado privado não expirava com a janela oculta | Poll e expiração precedem retorno de janela oculta; teste sem renderização |
| Menus de seleção permaneciam sobre o formulário após escolher ação | Fechamento explícito dos popups; reteste nativo do catálogo/local |
| Paginação de workstreams limitada às primeiras opções fixas | Deslocamento numérico validado, sem teto artificial de páginas no seletor |
| Falha do trabalhador de autenticação deixaria busy preso | Canal desconectado libera UI e informa interrupção, sem repetir solicitação |
| Relatórios com mais de 200 campos pareciam completos | Aviso explícito de objeto parcial; mantém limites de texto/profundidade/listas |
| Propostas negadas/atrasadas poderiam aparentar zero | Contagem opcional, escopo explícito, freshness e indicador 200+; teste de permissão negada |
| Documentação de instalação apontava release antiga e negava funções novas | URLs/versionamento, Keychain, login, administração e dependências atualizados |

Smoke nativo usou cópia isolada do app e servidor HTTP sintético. Confirmou
login humano/capacidades, formulário, prévia GET, campos bloqueados, botão de
execução desabilitado antes da frase exata, um único POST confirmado, CSRF sem
Bearer, senha retornada oculta, revelação e limpeza explícitas. Inspecionou
formulários Docker/LaunchAgent sem executar controle no serviço real.

Testes não tocaram Keychain real, não criaram usuários/chaves reais, não apagaram
memórias e não pararam/atualizaram Docker ou LaunchAgent do usuário. A coleta
nativa de recursos fez somente leituras locais. As operações de host foram
validadas com processos/arquivos sintéticos; não equivalem a homologar atualização
de uma instalação real nem a restaurar um backup real.

## Verificações

- Fmt, Clippy com warnings como erros e `git diff --check`.
- 70 testes aprovados em Apple Silicon e 70 em Intel via Rosetta, zero falhas.
- DMG Universal: assinatura ad hoc, arquiteturas, montagem, cópia e execução após ejeção.
- Fonte publicada e strings do binário revisadas com Gitleaks; sem dados da instalação.
- CI deve aprovar o HEAD final antes de merge; publicação exige verificar tag, assets e download público.

Zero achados acionáveis abertos nas passagens locais. Limites de API, recuperação
orientada, assinatura ad hoc e ausência de validação em hardware Intel/macOS antigo
estão documentados e não são apresentados como provas que não foram realizadas.
